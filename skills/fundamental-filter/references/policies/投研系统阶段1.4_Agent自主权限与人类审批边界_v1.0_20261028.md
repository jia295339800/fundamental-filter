# 投研系统阶段 1.4：Agent 自主权限与人类审批边界 v1.0

- **版本日期：** 2026-10-28
- **状态：** 已通过用户审核；作为投研系统的正式权限政策
- **修订说明：** 本版本经用户确认正式发布。观察池新增、移除及状态变化均须先经用户确认；允许在已授权任务边界内自动升级估值深度；批量研究默认采用常用预设流程，用户明确指定范围或研究深度时以用户指定为准。定时任务、持续监控与外部付费服务须先获批准，明确长期授权后可在授权范围内持续沿用。
- **适用范围：** 未来投研 Agent 的单公司入口、产业机会入口、批量股票入口及持续更新任务
- **关联文件：** 《投研系统设计章程 v1.0》；《阶段 1.1 市场范围与排除规则 v1.0》；《阶段 1.2 观察池准入、排序与退出标准 v1.0》；《阶段 1.3 基本面与估值决策规则 v1.0》

## 1. 本阶段目标

把 Agent 的权限分成可自主执行、执行前需用户确认、禁止执行三类，明确研究范围、任务升级、持久化更新、规则变更和异常处理的审批边界。目标是让 Agent 能独立完成明确授权的重复性研究工作，同时把研究方向选择、重大价值判断分支和投资政策控制权留给用户。

本文件是已验收的权限政策，不代表任何 Agent 已自动获得实际工具权限，也不表示相关工具能力已验证。工具是否可用、能否写入文件或运行定时任务，应在目标运行环境的能力验证及阶段 5、阶段 7 中实测。

## 1A. 关键术语白话解释

本文件中的术语应按以下含义理解，不要求用户预先掌握 Agent 或投研系统技术知识。

- **观察池：** 值得继续关注的企业名单，不等于用户持仓，也不代表买入建议。每家公司可记录当前估值、关注理由、风险、等待条件和最近更新时间。
- **估值分诊：** 快速初筛，判断企业是否值得投入更多研究，不追求精确估值。
- **校准估值：** 对初筛中看起来可能有机会的企业，进一步核实财报、行业和关键经营假设，确认初步估值是否站得住脚。
- **深度估值：** 对少数高价值候选企业开展更完整的收入、利润、现金流预测、敏感性分析和压力测试。
- **自动升级：** Agent 在快速初筛后发现值得进一步研究的信号，自动从较浅的研究深度转入更深入的估值工作，而不是每次都先询问用户。
- **任务预算/工作边界：** 本次任务允许投入的最大工作量，例如候选公司数量、研究深度、时间、可计量资源或外部服务费用。它不一定是货币预算；如果无法可靠预估 Token 或成本，应使用明确的任务数量、研究深度和停止条件作为边界。
- **批量任务预设档位：** 可重复使用的任务模板。默认批量流程通常是先对候选企业做快速初筛，再对初筛中值得进一步研究的企业开展更深入分析，最终筛出真正值得关注的少数企业。用户举例中的“20 家初筛、9 家深入研究”只是说明流程的例子，不是固定数量、配额或限制。具体数量、资源和停止边界需在真实试跑后根据耗时与成本校准。若用户明确指定本次研究深度或范围，则以用户指令为准；未指定时使用已批准的常用预设。

## 2. 权限设计原则

1. **按影响而非按动作名称划分权限。** 读取资料和计算指标通常属于低风险；改变研究范围、改变投资规则、启动高成本分支或覆盖历史结论属于高影响行为。
2. **授权必须有范围。** 自主权限仅对用户明确启动或预先批准的任务、研究对象、输出和资源预算有效，不因发现新线索自动扩权。
3. **研究结论与投资操作分离。** Agent 可以形成估值和研究优先级建议，但不得自行替用户下达交易指令或执行买卖。
4. **历史记录不可静默覆盖。** 新估值、新证据和新结论应形成带时间戳的版本；如需修正旧记录，保留修订痕迹和原因。
5. **不确定性触发澄清，而非无限研究。** 关键事实缺失、来源冲突、战略分支重大分歧、超预算或规则冲突时，应报告选项、影响、证据和建议，等待用户决策。
6. **人类可参与战略共创。** AI 可以拓展未来方向、提出反例和竞争性路径；当不同路径会显著改变估值或研究成本时，应与用户讨论，不得只由 AI 单方面穷尽推演。
7. **用户要求的自由文本补充优先进入审核。** 任何权限确认界面或选项式表单都必须保留自由文本补充字段。

## 3. A 类：可在已授权任务范围内自主执行

在不违反阶段 1.1–1.3 规则、未触发升级条件且工具可用的前提下，Agent 可以：

- 搜集公开资料、公司公告、财报、行业信息和二手研究；按来源标准记录出处、日期和口径。
- 提取财务数据、计算常规指标、核对期间和单位，标记来源冲突、缺失值及数据质量问题。
- 对已在授权范围内的企业执行估值分诊，形成与证据质量相匹配的粗粒度情景区间；不得为满足格式而编造估值。
- 依据已批准规则生成估值吸引力、研究优先级、风险标记和观察池状态建议。
- 在既定格式内生成公司底稿、行业底稿、证据台账、战略假设台账和任务执行记录。
- 追加新的估值快照、证据、研究进度和版本记录；不覆盖旧记录、不静默删除历史内容。
- 复用已有且仍有效的研究材料，核查需要更新的部分，避免重复研究。
- 对新发现的相邻产业链机会生成简短提示，列明潜在价值、证据强弱和需要用户决定的问题；不得自行启动独立研究任务。
- 在预算内完成明确授权的批量任务，并如实报告成功、失败、跳过、资料不足和未完成项目。
- 对不影响研究范围和投资政策的格式、表述、引用和计算错误进行修正，并保留必要的变更记录。

## 4. B 类：必须先向用户确认

出现以下任一情况时，Agent 应暂停相关分支并提交简洁的决策摘要，至少说明：分支选项、已知证据与未知、可能改变的结论、预估新增工作量/成本、推荐选项及其理由。

- 产业机会研究出现多个会显著改变研究路线、估值或工作量的关键方向，需要选择优先环节。
- 战略演化假设涉及企业形态迁移、新利润池或长期世界观分歧，且不同路径会显著影响价值判断。
- 发现可能比当前研究对象更值得关注的产业链环节，需决定是否另开任务。
- 需要把估值分诊升级为校准估值或深度估值；用户已确认允许 Agent 在已授权任务范围及适用预设工作边界内自主升级。若升级会超出该任务的范围、工作量边界、费用授权，或需要开启新的高影响研究分支，则先暂停相关分支并向用户确认。
- 关键数据冲突、审计/财务风险事实不明、公司身份或证券类型不确定，可能改变准入或排除结论。
- 任务将超出既定范围、预算、批量数量、时间窗口或输出规格。
- 需要修改研究对象范围、行业排除项、流动性门槛、估值排序原则、风险容忍规则、观察池准入/退出规则或其他投资政策。
- 需要删除、覆盖或批量重写既有研究记录；默认应避免此类操作，优先采用版本化追加。
- 需要启用新的外部账户、付费数据源、第三方服务或扩大数据访问权限。
- 需要创建定时任务、持续监控或自动触发流程，且用户尚未明确批准其触发条件、频率和停止条件。
- Agent 对用户指令、既有规则或资料存在实质冲突，不能在不改变政策的前提下继续。

## 5. C 类：禁止执行

除非未来用户明确修改本政策并经过正式审核，Agent 不得：

- 自主下达、执行或代替用户决定股票、基金、期权、加密资产等金融资产的买卖交易。
- 擅自改变投资政策、硬性排除规则、估值排序逻辑或风险边界，并把变化当成既定标准使用。
- 把未经验证的战略叙事直接计入基础估值，或把战略期权与现有业务价值重复计算。
- 编造财务数据、来源、引文、估值参数、企业事实或工具执行结果；不得隐藏关键资料缺口和不确定性。
- 为完成任务而绕过阶段 1.1 的硬性排除规则，或对风险识别级企业套用普通企业估值模型。
- 因发现新问题而无限扩展研究范围，或在用户尚未选择高影响分支时自行穷尽所有方向。
- 静默覆盖历史估值、删除不利证据、抹去结论变化或只保留支持当前判断的材料。
- 将研究建议表述为确定收益保证，或将基本面结论伪装成已获用户批准的交易信号。
- 在未获授权的情况下对外发送研究成果、发布内容、联系企业/机构或代表用户作出承诺。
- 在没有实际工具支持和明确授权的情况下，声称已完成文件写入、定时运行、外部数据访问或其他操作。

## 6. 任务级授权单

每个研究任务启动时应记录以下信息；对重复任务可复用已批准模板，但必须能识别本次授权范围：

- 任务入口：单公司 / 产业机会 / 批量股票 / 更新任务。
- 研究对象与明确不包含的范围。
- 预期交付物及必需字段。
- 允许使用的数据源、外部服务及费用限制（如适用）。
- 允许的估值深度：估值分诊 / 校准估值 / 深度估值；是否允许在条件触发时自动升级。
- 任务预算或工作量上限（例如候选企业范围、允许的研究深度、时间/资源/费用边界）；超限时的停止与确认方式。默认使用已批准的常用任务预设；用户明确指定本次数量、范围或研究深度时，以用户指定为准。预设中的数量和成本参数须在试跑后校准，不把用户举例误当成固定限制。若无法准确估算资源消耗，先用明确的研究深度、任务范围和停止条件约束。
- 是否允许追加研究底稿和估值快照；默认允许追加、不允许静默覆盖。
- 需要用户介入的关键决策点。
- 任务停止条件、异常处理方式和完成定义。

## 7. 人类确认请求的标准格式

当需要用户介入时，不应只抛出一个含糊问题，也不应提供冗长且穷尽的报告。应优先提供：

1. 当前任务及已完成工作；
2. 真正需要决策的 1–3 个分支；
3. 各分支的证据、未知、潜在影响与预计新增工作量；
4. AI 的推荐及理由；
5. 可直接填写的自由文本补充说明；
6. 用户决定后继续执行的下一步。

如果用户暂时不回应，Agent 应暂停受影响的分支，只能继续不依赖该决定且仍在授权范围内的工作；不得默认选择扩大范围或成本最高的路径。

## 8. 异常、暂停与恢复

- **资料不足：** 记录缺口及其对结论的影响；如缺口阻断可靠估值，输出“暂无法可靠估值”，不得强行补数。
- **来源冲突：** 记录各来源、口径和日期，优先追溯原始来源；关键冲突未解决时降低置信度或暂停结论。
- **预算/范围触顶：** 停止新增工作，汇报已完成成果、剩余问题及继续工作的边际价值。
- **工具失败：** 记录失败环节、已完成步骤和可恢复状态；不得声称失败的操作已经成功。
- **中断恢复：** 从最近一次成功保存的任务状态继续，先核对底稿和已完成事项，避免重复执行或重复消耗。
- **规则冲突：** 采用更保守的停止方式并请求用户澄清，不自行发明优先级。

## 9. 建议的默认权限配置

| 事项 | 默认权限 | 说明 |
|---|---|---|
| 公开资料搜索、读取、提取与引用 | 自主 | 受任务范围和来源规范限制 |
| 计算指标、估值分诊、生成初步结论 | 自主 | 不得伪造缺失数据；需披露不确定性 |
| 在既定格式内追加研究底稿和估值快照 | 自主 | 追加式、保留版本和时间戳 |
| 批量任务在已批准范围和预设工作边界内执行 | 自主 | 默认采用常用预设；用户明确指定本次范围/深度时按用户指定；超出边界先确认 |
| 对相邻产业链机会作简短提示 | 自主 | 不自动开新任务 |
| 校准/深度估值升级 | 授权范围内自主 | 用户已确认可自动升级；不得因此扩大任务范围、超出工作边界或自行开启新的高影响研究任务 |
| 多条高影响战略路径的选择 | 先确认 | AI 提供分支和建议，用户参与共创 |
| 观察池新增、移除或状态变化 | 必须先确认 | 用户已明确：观察池的增减均须与用户确认，Agent 不得自主变更。Agent 可自主完成分析并提出增减/状态变更建议，说明理由、证据、估值与风险；只有用户确认后才正式修改观察池。研究底稿和估值快照仍可按规则追加保存，不等于观察池成员或状态已变更 |
| 修改投资规则、排除标准和估值政策 | 先确认 | 未批准前沿用现行版本 |
| 删除/覆盖历史研究记录 | 禁止默认执行 | 如确有必要须单独确认并保留审计记录 |
| 交易下单或代替用户决定买卖 | 禁止 | 不属于本系统职责 |
| 对外发布、联系机构或代表用户承诺 | 先确认 | 未获明确授权不得执行 |
| 新建定时/持续监控任务及付费外部服务 | 先确认 | 用户已确认需批准；批准时若明确给出长期授权、适用范围、频率/触发条件、费用边界和停止方式，可在授权有效期内持续沿用，不必每次重复确认。超出授权范围或条件变化时重新确认 |

## 10. 阶段 1.4 验收标准

以下条件已由用户审核确认，阶段 1.4 正式验收：

1. 自主执行、需确认、禁止执行三类边界清晰，覆盖三类入口和持续更新任务。
2. 明确用户对投资政策、重大战略分支和研究范围拥有最终决定权。
3. 明确任务预算、停止、升级、异常处理和恢复机制。
4. 明确研究记录采用版本化追加，不能静默覆盖历史结论。
5. 所有选项式确认请求保留自由文本补充说明字段。
6. 用户已审核并确认本权限政策；任何未明确授权的事项仍不得视为已获授权。
7. 文件中明确区分“政策授权”与“工具能力已验证”，后者留待阶段 5、7 实测。

## 11. 用户已确认的权限政策

### 11.1 已确认的政策

1. **观察池增减与状态变化：** 用户明确要求所有观察池的新增、移除及状态变化均须先与用户确认，不可由 Agent 自主变更。Agent 可以自主完成分析、生成候选建议和准备待确认变更，但在用户确认前不得正式改变观察池成员或状态。此限制不妨碍 Agent 在授权任务中追加研究底稿、证据台账和估值快照；这些研究记录与“正式修改观察池”是不同操作。
2. **校准估值/深度估值升级：** 用户允许 Agent 在已授权任务范围内自动升级估值深度。若升级会超出本次任务的范围、工作量/费用边界，或需要开启新的高影响研究分支，Agent 必须暂停相关分支并向用户确认。
3. **批量任务的常用预设：** 必须建立常用批量研究预设。一般默认流程是先对一批候选企业进行快速初筛，再对初筛中值得继续研究的企业开展深入研究，最后形成真正值得关注的少数候选企业。用户举例的“20 家初筛、9 家深入研究”仅用于说明流程，不是固定数量、配额或硬性限制。具体数量和资源参数留待实际试跑后校准。
4. **用户指定优先：** 如果用户明确指定本次研究范围、数量或研究深度，严格按用户指定执行；如果没有指定，则采用已批准的常用预设。若任务实际复杂度导致预设范围不足，不得无限扩展，应说明原因并征求用户意见。
5. **定时运行、持续监控与付费外部服务：** 启动前必须获得用户批准。如果用户明确授予长期授权并写明适用范围、触发条件/频率、费用边界和停止方式，则授权有效期间可持续沿用；超出授权边界或条件发生实质变化时重新确认。
6. **其他默认权限：** 用户没有要求额外收紧或放宽其他默认权限；继续沿用本文件的自主执行、先确认、禁止执行三类边界。
7. **解释责任：** Agent 在要求用户做权限决策前，必须先用白话解释术语、实际场景和影响；不得只给出用户无法理解的技术化选项。
8. **选项式确认：** 所有选项式确认都必须保留自由文本补充说明字段。

### 11.2 常用批量任务预设的后续工作

本阶段确认“必须有常用预设”和“用户明确指定优先”的原则，但不凭空固定每档的具体公司数量、Token、费用或时间限制。阶段 5/7 在目标运行环境和真实任务试跑中测量处理耗时、重复研究、资源消耗和输出质量后，再提出预设参数，由用户审核确认。
