# 取证、复核与续跑

## 任务范围与完成标准

明确完整研究直接执行本流程，复用旧快筛及原件但不接受旧优先级的停止指令。交付实际商业模式与竞争/经营驱动、财务风险、必要经营预测、资本与股东现金关系、选法和可复算价值/价格要求，并说明主要反证和改判条件。对缺证部分保留条件或C，不用一句高估/低频替代完整任务，也不用已有计算结果当成整份研究已完成。

定向问题只执行有关取证和分析：界定主体/范围/期间，回答指定问题，说明证据、计算关系与不确定性。已形成经营/投入/现金表时仍用原共享检查；无股价估值需求时不强制三情景、全套准入卡或完整研报。硬排与准入约束普通估值/入池，仍可核实指定经营和风险事实，不能冒称规则已放行。

## 自动取证

单股完整研究沿用本页；批量筛选或未指定深度的开放任务按[研究深度与复用](research-depth.md)安排。用户点名升级或自主选中深研后复用原件、快筛与关键问题结果。`entry.py`及`collector.py`可选`--cache`共享原始请求；正式准入与估值要求不变。

先在运行目录旁保存用户的证券名单、基准日和候选理由。当前脚本适配 11–12 月深圳 A 股，须由深交所名录返回与请求日一致的快照。运行环境为 macOS、Python 3.9+、curl 和 Swift PDFKit。自动取证每证券最多 24 个 HTTP 调用和 180 秒，下载归档保留原文、日期与 SHA-256。

```sh
PYTHONDONTWRITEBYTECODE=1 python3 /path/to/fundamental-filter/scripts/entry.py 2026-11-06 /path/to/new-run 002677.SZ 002003.SZ
```

仅用户明确点名且需要核市值例外时，对该代码附加 `--small-cap CODE.SZ`。低于门槛的对象可继续取证，补齐实际成交需求及其他准入后进入「点名单列」。

读取运行目录的 `当前结果.json` 找当前结果单。硬排写入后收口。待核样本根据 `证券/取证快照.json` 指向的取证目录读取 `自动准入.json`、原文、`来源索引.json` 及有则读取 `补充取证.json`。PDF 文本用作定位，碰到列错位、复选框字形、扫描图或附注时核对对应 PDF 原页。比较期重述与报告金额以主体、币种、合并范围和同期间对齐后判断。公告来源优先交易所、法定披露平台与公司正式报告，行情使用不复权收盘和同日股本，金额、股数或股权范围冲突则区分能否判门槛与能否做每股估值。

其他市场或日期采用证据复核路径。先按同一 v1.6 核实官方上市状态、审计与报告原件、交易基准和适用准入，保存可定位的原文清单。正式准入与估值使用包内 `entry.py formal /path/to/复核记录.json`，缺关键项时输出待核；`calculate.py`保留为旧冻结输入的数值复算，不作为新任务正式准入交付。该路径的取证和政策判断由宿主执行，跨市场自动覆盖尚在试用验收范围之外。

## 必查披露正文覆盖

正式准入、估值或入池前执行；批量初筛可先标「准入未完整核验」，定向经营问题只取相关证据。原件存在、下载成功和文件哈希均不代表正文已审查。

先保存 `披露请求.json`：`证券`（如601801.SH）、`基准日`（YYYY-MM-DD）和`证据`列表。每份证据包含 `id`、`文件`（相对请求文件或绝对路径）、`SHA256`、`公开日`、`版本日`、`日期依据`、`URL`（原始HTTPS地址）、`证券`（代码列表）。复用已核的原件索引，纳入适用年报、审计及已知相关更正公告；PDF使用原包PDFKit提取，归档文本须带`=== PAGE N ===`原页标记。提取器仅定位章节，不判定事项性质。

```sh
python3 /path/to/fundamental-filter/scripts/entry.py disclosures extract 披露请求.json 披露正文.json
python3 /path/to/fundamental-filter/scripts/entry.py disclosures show 披露正文.json 重大及前期差错更正
```

实际阅读输出中三个主题的全部正文和规则；工具输出截断时逐主题`show`。缺章、扫描提取失败或截断须补取原页，不能填成不适用。管理报告与附注可能使用不同适用期间，不可只选附注里的不适用而忽略管理报告已适用的事项。现入口优先覆盖审计意见、会计政策及估计变更、重大及前期差错；其他必查准入仍按原流程核实。

在原复核卡增加 `披露覆盖`：`文件`（相对复核卡的披露正文JSON路径）、`SHA256`、`复核`（三个主题各一条）。每条填写：

- `项目`：审计意见、会计政策及估计变更、重大及前期差错更正。
- `正文id`：该主题全部提取段落的id；`适用状态`：适用、不适用或待核；`判断`：实际审阅的意见/原因、影响及期间；`规则条款`：如§2.3及适用分项。
- `追溯事件`：原卡`追溯复核`的零起始下标列表。政策或差错适用时必须关联事件，事件`证据`使用对应段落的`引用`。沿用现有类型与`review_restatements`；纯列报调整补准则和三个核心总额，不按章节标题机械硬排。无事项填空列表，未知填待核，不能发明事件。

正式入口重新核验原件、主体、公开/版本日期和原文，验证复核及事件衔接；覆盖不全则准入待核，不交付正式价格。宿主仍负责理解正文、分类事项、判审计意见与核其他准入，程序不能证明模型真的注意到每句话。明确硬排可按原流程停止，不为凑齐其他正文而继续无用研究。`entry.py check`只做研究算术，可在准入待核时使用，但检查通过不是放行。

## 写复核卡

在对应证券目录创建 `复核记录.json`。沿用取证 SHA-256；如有补充取证，使用其索引文件 SHA-256。每项判断附快照文件名及可选的 `#page=N`，外部增补原文另列已核验的 HTTPS 来源。对于负证据，保留检索范围、截至日和未覆盖部分。判断可以是「待核」「硬性排除」「强化审查」「继续初筛」。其中「继续初筛」「强化审查」要求适用准入已复核。

| 复核卡字段 | 填写口径 |
| --- | --- |
| 证券、行情时点、取证指纹、来源指纹 | 从自动准入和取证快照读取 |
| 补充指纹 | 存在补充取证索引时必填 |
| 全部适用准入已复核、准入 | 布尔值与研究路由 |
| 检查 | 市场与交易、披露与审计、资金占用、诚信与行业、强化风险。每项为 `{"判断":"…","证据":["原文.pdf#page=1"]}` |
| 剩余待办、关注 | 证据缺口清单和去留建议 |
| 诚信时效复核 | 已确认重大财务造假或重大违法违规时逐案填写。字段为 `正式认定日`（YYYY-MM-DD，缺证填 null）、`现时重大影响`（true、false 或 null）和 `证据`（正式认定及当前核查来源）。`准入` 先填其他独立规则的结论，脚本再合并此项分流。 |
| 追溯复核 | 按事件逐项填 `类型`、`证据`。类型为纯科目改列、实质政策变更、重大会计差错、待核、同控合并、仅每股重算。纯科目改列另填 `准则依据`，`核心总额` 包含净利润、净资产、经营现金流净额，各填未变、变化或未核。见下文 |
| 小市值复核 | 仅点名单列使用。填写 `成交需求判断`、`满足成交需求`（真、假或未核用 null）和 `证据`。判断中写明用户实际下单规模、分批安排及对应流动性依据 |
| 估值缺口 | 准入完成后，缺当前模型必要输入时逐项列明缺口和重评条件，保留准入并输出估值待核 |
| 排雷底稿 | 能可靠取到的财务比较，见下文 |
| 估值卡 | 通过准入后按[估值卡](valuation.md)构造 |

研究形成可检查的经营或现金表后，先执行[研究表接入共享检查](valuation.md#研究表接入共享检查)，保存同一输入和检查输出，再写最终结论。准入缺证时可单独检查研究算术，正式估值仍受本节准入路由约束。

### CFO和购建支出的有限核验（v0.6.2维护版）

历史CFO、购建支出用于现金判断时，放入原`排雷底稿.数值`，并在该底稿附`现金原表核验`。自动提取成功只代表取得候选金额。原页本期列尚未确认、跨页错列或空值时，保留待核；不得仅凭PDF线性文本先后推定期间，也不将空值填0。

`entry.py cash-check 研究复核包.json`复用同一研究输入，校验固定的两条关系：CFO=经营流入小计−经营流出小计；购建=投资流出小计−投资支付−取得子公司支付−其他投资支付。原`formal`和批次复核也默认调用此核验；未核本期现金字段不参加原排雷现金比较，准入及不依赖该字段的研究保留。旧`calculate.py`仅供冻结数值复算，行为不变。

`现金原表核验`给`证券`、`本期末`、`单位:"元"`、`原件:{文件,SHA256,URL}`和`字段`。字段键为上面两条关系对应的科目：`经营现金流`、`经营现金流入小计`、`经营现金流出小计`，或`购建支出`、`投资活动现金流出小计`、`投资支付`、`取得子公司支付`、`其他投资支付`。每项含`金额元`、`原文值`、`本期末`、`页码`、`表头页码`、`本期列已核:true`、`列归属方式:"原页核对"`、`列归属依据`。分属两期或未经确认的其他项不能参与反推；仅在原页明确为0并已确认本期列时给0。

原件金额与同表小计保持元口径核对。研究底稿若使用舍入后的亿元值，只在对应的上述`字段`记录附`研究金额舍入:{单位:"亿元",小数位:2,方式:"四舍五入"}`，小数位限0—10；程序要求研究值严格等于原件按该精度四舍五入的结果，不推断数字位数或放宽统一容差。通过后，用原件精确金额参与本次现金比较，输出保留研究输入及比较方式，原输入不改写。未声明舍入仍按原精确金额核对。

核验绑定原件哈希、声明期间和固定小计关系，不能证明宿主确实看过原页，也不会自动恢复PDF空间表格。金额、符号或列归属冲突、缺小计或缺原页确认均返回待核，不补造金额。只有影响当前结论的字段需要这项有限核验；禁止把未核现金差额当股东自由现金流。估值输入若另行引用这些未核字段，其依赖结论也须留待核，不能用PE或共享算术通过代替来源核验。

估值卡可按[经济关系输入](valuation-calibration.md#可重算的经济关系输入)补充来源与勾稽。`经济关系`和`等级依据`内的证据也使用现有原文校验；关系矛盾时保留准入，估值转C待核。B条件值无需强建完整DCF。候选版与旧版使用不同运行目录，批次指纹包含`economics.py`，避免在旧冻结结果上续写新版计算。

检查引用需要能指向原件。市场项覆盖交易所名录、同日市值、日线。披露项覆盖年报、审计、三季报。占用项覆盖年度、半年度专项。诚信与行业至少用年报。强化风险至少使用半年报和三季报。使用相同命令恢复。旧结果留在 `结果快照`。新日期、规则更新和模型版本变化开新批次，文件源快照可在同日期与相同取证版本下通过 `--reuse` 复用。

追溯复核应由宿主核对原页及同口径财务数。分别记录会计准则首次执行、股本重算和差错更正；有多项调整按最严格分流。已核实纯改列用同口径历史数据，实质变更转强化审查。保留事实与改判依据，核心总额未核则待核。

人工路径使用相同的 `追溯复核`、`诚信时效复核` 和 `估值缺口`。已确认事项按 §2.3.2 定向查当前影响。调查与指控在其他准入判断记录。使用 v1.5 做出的旧案结论开新批次复核。填入已核实的 `市值门槛判定`（达标、未达标或待核）。对小市值例外另显式填 `研究范围: 点名单列`、`点名小市值: true` 和 `小市值复核`。有其他硬排仍停止。点名单列的估值只进条件演算。

## 排雷底稿

以同主体、同币种、同合并范围填入人民币亿元。毛利率填小数，周转率填倍数。字段为 `本期末`、`同期末`、`期初`、`同期可比`、`数值`。每个科目存 `本期`、可选 `同期` 或 `期初`、`证据` 列表。现金流和利润取同累计区间，净应收同比取相同季末。只有期初余额时单列期初变化。

支持营业收入、合并净利润、经营现金流、购建支出、净应收、毛利率、存货周转率、货币资金、有息负债、总资产。脚本分别列出已算检查、线索和缺数。现金和有息负债各达总资产 10% 是试用线索阈值。现金流减购建支出包含扩产，结合原文拆解。出线索时优先核回款、账龄、资产受限、负债用途或扩产，结合行业和季节性决定风险分流。
