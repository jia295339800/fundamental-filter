# 研究深度与原件复用

## 适用范围与显式任务

这里的深度调度服务于批量筛选及未指定深度的开放任务。明确完整研究直接走workflow.md，不先提交快筛五问，也不因旧低频/停止结论缩短商业分析。明确定向问题直接研究该问题，不强制整套报告或普通估值。调用本调度入口记录交接时，顶层或公司项写`任务:{类型:完整研究/定向问题/批量快筛/自主调度,目标:用户要解决的问题}`，公司项覆盖批次任务；省略任务兼容原自主调度。该声明由Agent按用户请求填写，不要求用户学习模式名。

显式完整研究/定向问题在程序中先于快筛优先级处理；输出的是执行指向，不证明研究已完成。完整研究交付以经营、资本、现金、估值方法与证据边界的实际研究为准，已有价格计算结果不能单独证明完成。定向任务交付事实和条件回答，准入待核、估值C或历史低频不阻止回答可核实的具体问题；普通估值和入池仍服从原准入，硬排不被豁免。

## 决定下一步

批量/开放任务先用已存研究、最新行情和主要财报回答五问：靠什么赚钱、经营有哪些变化、价格要求什么、何种因素阻断继续研究、哪项信息最能改变决策。只核能左右本轮研究价值的数字；快筛不声称已经完成全部准入或精确估值。显式完整研究可以停止无关旁支，仍完成用户要求的核心分析。

Agent按跨公司的决策价值和取证可得性安排执行顺序，先处理能以较少资源改变去留的问题；输入`公司`顺序即执行优先序。程序按此顺序生成统一`任务队列`及稳定任务ID，低频、暂停和已交付项不再入队。它不自行按财务指标评分或给深研/补证固定优先级；排序理由写在公司的经济判断中。

把最关键的问题拆成至少两个有经济理由的答案分支。例如“投入上限A且利润可持续→继续；投入明显超B且现金不能覆盖→停止”，取证目标应是能区分分支的具体原件/数据。边界由企业证据形成，不设统一PE、利润增速或CFO阈值。若各答案都值得研究，跳过该细节进入完整研究；若各答案都不改变低频/停止判断，则结束该项补证。可能改判且资料可取得才做定向取证。取证后更新事实及分支，不能只把问题改写一遍。

停止或低频前，用本企业适用的反面线索检查短期数字是否遮蔽价值：周期正常盈利、研发与新品投入、转型/资产兑现等；适用项由Agent选择。机会线索不足不等于机会不存在；没有足够事实建立边界时保留“未解决”，不以高PE、利润下降或负现金流直接淘汰。

补证已经查过仍缺或暂不可得时，写明查过什么、为什么不能决定、什么事件可重启，暂停主动检索。对仍有机会的企业保留条件判断，避免无限续跑同一问题。资源预算是任务边界，耗尽记“未完成”，不是基本面否定。无固定晋级层数、入选比例或每公司任务数。

## 执行与交接

调度的商业判断由Agent形成，程序不替代它。把正常研究五问、原件清单和关键分支交给同一入口，输出下一动作及原因：

```sh
python3 /path/to/fundamental-filter/scripts/entry.py research route /run/研究输入.json /run/调度
```

输入顶层为`基准日`（信息截止）、`证据`列表及`公司`列表；盘中正式研究使用上一交易日收盘时另列`行情基准日`，默认两者相同，行情日不能晚于信息截止。历史研究的信息截止必须仍为原冻结时点，不可为迁就新文件而放宽。证据每项含`id`、`文件`（相对输入文件或绝对路径）、`SHA256`、`URL`、`公开日`、`版本日`、`日期依据`、`证券`列表及`类型`；行情另含`数据日`。引用用id，程序拒绝串公司、日期越界、同日行情失配和失效原件。共享名录/指数可将证券声明为`共享`；公司财报按实际主体标注。日期和主体声明仍需Agent核原件，不能用程序接收代替核实。

公司每项含：

- `证券`；`快筛`中`赚钱机制`、`经营变化`、`价格要求`、`阻断因素`各为`判断`与`证据`；`价格要求`另带`行情证据`。
- `当前判断`含`行动`（继续/低频保留/停止本轮）、`理由`、`重启条件`。低频或停止另填`遗漏复核`的`分析`及`证据`，针对企业反证，不写通用套话。
- 有会改判的缺口时填`关键问题`：`问题`、`答案分支`（每项`条件`、`行动`、`理由`）、`取证目标`列表、`失败出口`；可写`可得性=暂无来源`或`取证状态=已查仍缺`暂停。取证结果与证据留在五问中，保存新输入，不覆盖前版。
- 已有完整研究时用`完整研究输入`指向原calculate.py输入。调度通过`entry.py formal`同一实现复核披露覆盖，再调用原计算入口，继承准入和共享经济检查结果，不另设估值公式。旧卡缺覆盖时继续有边界研究，正式准入待核。尚未复核准入时只能“进入完整研究”，不能冒称已获正式估值许可。

输入原件、判断和代码指纹构成续跑凭据；相同输入不创建重复任务。补证结果只改变当前时点研究记录，旧结论保持原样。完整研究直接接收已有快筛、原件和问题结果；原`entry.py check`和准入要求继续有效。

## 集中取证与成本

批量HTTP原件请求沿用collector的curl、超时及24次/180秒上限，自动采集入口可用`--cache /run/cache`共享同日名录、市场序列及同版本原件。也可直接提交请求列表：

```sh
python3 /path/to/fundamental-filter/scripts/entry.py research fetch /run/请求.json /run/原始资料 --cache /run/cache
```

请求JSON含`基准日`和`请求`列表，每项为`文件`、`URL`及可选`表单`。同批相同请求缓存命中不再下载；动态接口按基准日隔离，巨潮finalpage PDF按精确版本URL复用，原始字节用SHA256校验，损坏显式缺证。不同证券的文件和已核数据不互相替代。同URL缓存不能证明当前无修订，新的披露/修订需更新索引并核版本；需要重新确认动态响应时用新的缓存目录。失败响应留在请求记录，不能按成功计数。快照不可见的真实内容及公开时间仍需原有复核。

缓存只管理取回的原始字节。已存PDF文本和提取数据按原件SHA256、财报期间和提取口径复用；估值卡还须匹配价格日、股数和方法版本。跨时点复用旧年报允许，但须检查更新披露；旧报价和旧假设不能直接成为新时点结论。历史研究仍使用原history-search/history-release，新增缓存不放宽日期隔离。

各阶段保存真实开始/结束、HTTP尝试（含失败）、缓存命中、读取与新增原件、检查入口及去留变化。模型Token和费用有宿主凭据才汇总，拿不到写null及覆盖范围；调度脚本毫秒耗时不代表Agent研究耗时。比较成本须用同资料范围和实际执行的基线，不能把未执行的“逐股深研成本”估作事实。漏筛审查在初筛冻结后，额外复核一部分停止/低频公司；已见开发案例与新批次分开报告。
